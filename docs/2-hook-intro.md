# Section 1: Hook + Intro (2 min)

Two candidate versions for the opening 2 minutes. Pick one for the deck, or keep both as a fallback/A-B option.

## Option 1: Audience poll

**[0:00–0:15] Self-intro**
"Hi, I'm Ruturaj — [role/what you do with Drupal]. I've spent a good chunk of the last few years building interactive Drupal sites the traditional way, callbacks and all — which is exactly why I got excited when HTMX showed up."

**[0:15–0:45] Audience poll**
Two quick show-of-hands questions to read the room and set the stakes:
- "Show of hands — who's written a Drupal Ajax API command by hand?" *(expect most hands up — this is your "you know this pain" moment)*
- "Now, who's heard of HTMX before today?" *(expect a mixed/lower response — sets up that this is new territory for many)*

Optional one-line reaction depending on results: "Okay, so most of us have felt the pain, and only some of us know there's another way. Let's fix that."

**[0:45–1:00] Framing quote**
> "The future of Drupal UX isn't more JS. It's smarter HTML — with HTMX."

**[1:00–1:45] Arc preview**
"Over the next 45 minutes, we'll do four things: look at why Ajax API gets painful at scale, learn HTMX's core idea, map that idea directly onto Drupal's render/routing/caching system, then watch it work live — building a form, a filter, and a partial update with barely any JavaScript. We'll close with how to compare the two honestly, and how to bring this into a project you already have."

**[1:45–2:00] Transition**
"Let's start with where we are today — the Ajax API."

2. Confirm the poll reaction line, or swap for a different angle on the pain-point → knowledge-gap → "let's fix that" beat.
